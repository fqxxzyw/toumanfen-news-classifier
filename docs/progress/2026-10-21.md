## 实际结果与验证范围

### 模型大小

| 权重 | 大小 |
| --- | ---: |
| FP32 model.safetensors | 390.1718 MiB |
| INT8 model_state.pt | 145.9637 MiB |
| 压缩倍数（原始 / 量化） | 2.6731 |

74/74 个 Linear 层已量化。另起进程恢复权重，完成三条真实新闻的批量 CPU 推理与重复推理一致性检查。Embedding、LayerNorm 等仍使用浮点数，不能把该模型理解成所有参数和运算均为 INT8。

### 分类质量流程验证

测试文件前 64 条全部属于 education 类。FP32 和 INT8 的 Accuracy 均为 0.953125（95.31%）；按完整十分类计算的宏平均 F1 均为 0.0976。该数据只验证两个流程能执行，不是全量 test 成绩，也不足以证明量化无精度损失。

### CPU 延迟流程验证

固定输入形状 `(1, 22)`，CPU 4 线程，预热 1 次、计时 3 次，输出每批延迟：

| 模型 | p50 / ms | p95 / ms |
| --- | ---: | ---: |
| FP32 | 98.025 | 116.466 |
| INT8 | 2318.776 | 2367.840 |

这是少量试跑，不是稳定性能基准。在该次运行中 INT8 比 FP32 慢，说明文件压缩不能直接等同推理加速；正式对比需要更多预热与重复次数，并固定后台负载、输入、线程及后端环境。

## 运行入口

以下命令从仓库根目录执行。LLM 批量预测会实际使用本地配置调用外部 API；评估已有 CSV 不调用 API。

```powershell
python 05_LLM/src/prodict-one.py
python 05_LLM/src/evalute.py
python 05_LLM/src/api.py

python 06_model_quantization/src/quantize_model.py
python 06_model_quantization/src/model_compare.py
python 06_model_quantization/src/evaluate.py --max-samples 64 --batch-size 8 --threads 4
python 06_model_quantization/src/benchmark.py --batch-size 1 --warmup 1 --repeat 3 --threads 4
```

评估完整测试集时移除 `--max-samples 64`。当前 LLM 批处理教学版不支持 --limit 等命令行选项，修改输入路径需调整 config.py；更换数据源前应备份并更换结果 CSV，避免旧 row_id 与新数据混用。
